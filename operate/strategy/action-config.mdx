## Three decisions

1. `rules` decides whether the strategy is eligible.
2. `action_config.size_expr` produces the first action's positive integer input amount.
3. `execution_params.plan.steps` describes hook order, effects, parameters, and amount propagation.

A true trigger does not fix a wrong denomination. A positive size does not prove sufficient balance, authorization, or liquidity.

## Action fields

| Field | Contract |
|---|---|
| `action` | Directional enum such as `DEPOSIT`, `WITHDRAWAL`, or `REBALANCE` |
| `size_expr` | Numeric expression converted to integer raw input units |
| `objective` | `BALANCED`, `MIN_SLIPPAGE`, or `MIN_TIME` routing objective |
| `from_address` | Vault/account context; not necessarily the token-holding strategy contract |
| `target_address`, `target_type` | Target and canonical family such as `ERC4626` or `VAULT` |
| `execution_params.strategy_address` | Strategy execution contract |
| `execution_params.plan.steps` | Ordered registry-selected hook metadata and arguments |
| `max_slippage_bps` | End-to-end slippage budget; positive when a plan consumes one |
| `max_duration_seconds` | Deadline policy; deferred plans have additional duration requirements |

Legacy top-level `execution_name` and `execution_address` are not the current plan contract. Generate hooks and arguments with the registry-backed editor. Do not invent addresses or mix encoded arguments with a different source/oracle.

## Input denominations

| Hook pattern | First input | Output |
|---|---|---|
| Approve + deposit ERC-4626 | Raw underlying assets | Received source shares |
| Redeem ERC-4626 | Raw source shares | Received underlying assets |
| Aave V4 borrow | Raw debt-token amount | Received debt tokens |
| Aave V4 repay | Raw debt-token amount | Spent amount / debt reduction, not redeemed vault shares |

The VM returns a high-precision number. Intent construction truncates toward zero, rejects non-positive/infinite values, and rejects positive fractions that become zero. Adding `1` means one **raw** unit of the current denomination, not one human token.

These plans have immediate `EXECUTE` steps on the same chain and vault, intended as a bundled hook transaction. The historical AP1 record has one `hook_tx` fill. ## Sizing and verification

For a target repayment, apply `(debt value - target × collateral value) / debt value` to the raw debt amount, then cap by available funds. For redeem → repay, convert the desired assets to shares using PPS and the decimal difference, then cap by held shares and observed asset/share exit liquidity.

AP1's `0.99` liquidity cushion, `1.001` repayment buffer, and `0.9998` slippage factor are distinct controls. A liquidity cap can leave the target unmet. See [Variables and units](/operate/strategy/variables#assetshare-conversion).

Before publication, inspect freshness, input/output units, hook authorization, slippage, balances, session keys, and gas. After a fill, reconcile source shares, debt-token receipts, debt reduction, and residual tokens. Schema validation is not a transaction preflight or economic proof.
