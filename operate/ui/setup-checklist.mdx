## Setup rows

Open **Setup** with the intended chain and vault selected. The visible checklist summarizes configuration; it does not preflight every executable plan.

| Row | Evidence represented | Additional launch check |
|---|---|---|
| **Vault is created** | Indexed deployment exists | Verify chain, underlying, vault, and strategy addresses |
| **Upkeep is staked** | Reported activation state | Inspect actual balance, required threshold, and shortfall |
| **Hooks are set up** | At least one hook in the active config | Verify all plan leaves, generated root, onchain sync, and available proofs |
| **Yield sources are set up** | A source is whitelisted | Verify each intended source, oracle, unit scale, freshness, and liquidity |
| **Strategy is set up** | A strategy exists | Inspect definition/version, intended state, sizing, priority, cooldown, and concurrency |
| **Vault is live on Superform** | Distribution visibility/availability | Verify allocator-facing listing and redemption path before routing public deposits |

The displayed order is not a dependency scheduler. Configure source targets before authoring hooks and plans that reference them. An inactive saved strategy can satisfy an existence check without being approved to run.

## Execution readiness

- [Execution account](/operate/ui/execution-accounts): executor is an authorized manager, session is valid, and rotation is not incomplete.
- [Funding](/operate/ui/funding): UP upkeep, native execution gas, and strategy input assets are independently sufficient.
- [Hooks](/operate/ui/merkle-trees): intended configuration and onchain root agree; every plan step has usable authorization.
- [Strategy tests](/operate/ui/simulation): expressions and denominations have been checked; model limits are recorded. A model run is not a transaction preflight.
- [Operational state](/operate/ui/pause): no unintended vault pause, keeper pause, kill switch, or target emergency lock.
- [Monitoring](/operate/automation/monitoring): stale or unavailable observations raise an alert rather than becoming healthy defaults.

## Activation fields

| Field | Meaning |
|---|---|
| `activation.is_active` | Management service's activation decision |
| `activation.is_discoverable` | Eligibility for public discovery |
| `activation.status` / `activation.reason` | Reported state and optional explanation |
| `upkeep_info.balance` | Raw UP upkeep balance |
| `upkeep_info.threshold.required_balance` | Raw required balance for this chain/vault |
| `upkeep_info.threshold.shortfall` | Raw amount missing from the threshold; zero means sufficient |

Read current thresholds rather than hardcoding a chain minimum. The management implementation supports activation exemptions, so an active flag and positive shortfall are not necessarily contradictory. An exemption is not proof of funded gas, fresh PPS, or a working strategy. Investigate the balance and effective policy before changing funds.

## Private readiness versus public launch

A deployed, role-accessible vault can be prepared and tested privately. It need not be listed to author inactive strategies. Public launch adds distribution metadata, visibility, availability, and an approved depositor operating path. See [Distribution](/operate/ui/distribute).

If Setup and a detailed read disagree, inspect the underlying contract/API state and its freshness. Do not declare readiness from a green summary row alone.
