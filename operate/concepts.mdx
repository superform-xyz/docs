## Enforcement layers

| Layer | Responsibility | What it does not prove |
|---|---|---|
| Strategy Engine | Evaluate offchain rules, sizing, lifecycle, cooldown, and publication gates | A rule is not a contract-level restriction on every authorized manager |
| SuperVault contracts | Share accounting, ERC-7540 redemption flow, manager checks, pricing and fee constraints | A saved engine definition has been executed |
| Hooks and Merkle authorization | Check registered hooks and authorized parameter combinations against applicable roots | The selected action is economically appropriate |
| External venue | Apply its own collateral, debt, liquidity, transfer, and liquidation rules | That an entire planned unwind will complete |
| OMS | Process intents, construct execution, track events and transaction results | A completed record alone proves the target portfolio state |

Vault assets can be idle or deployed into external positions. For carry, the underlying asset, collateral, borrowed token, and yield-source shares are different assets with different units. Do not equate TVL with immediately withdrawable cash.

## Four separate changes

1. **Save a strategy:** an authenticated offchain mutation. Create/Save does not require a hook-root transaction and does not start a newly created strategy.
2. **Authorize hooks:** configure leaves, generate the tree, and update the onchain root through the applicable proposal and timelock. Publishing a downloadable proof artifact is a separate action.
3. **Start execution:** transition the strategy to `RUNNING` only after funding, permission, freshness, and plan checks. A true rule can still be blocked by publication gates.
4. **Reconcile the result:** follow intent, execution, fill, and receipt identifiers; inspect token, share, collateral, and debt changes.

[Lifecycle](/operate/strategy/lifecycle) covers state and concurrency. [Hooks](/operate/ui/merkle-trees) covers authorization.

## Accounting and operational readiness

PPS values shares in the underlying asset. It is not a guaranteed withdrawal quote or a promise of immediate liquidity. PPS freshness and validator acceptance matter independently of source price and position-data freshness. Performance fee skims can reduce PPS; see [Economics](/learn/supervaults/economics).

UP upkeep funds the protocol's upkeep system. Native-chain gas funds transaction submission. Depositor capital funds positions and redemption liquidity. None substitutes for the other two. See [Upkeep and gas funding](/operate/ui/funding).

## Access is not signing authority

A browser session identifies a user; a vault role authorizes particular requests. A wallet signature or delegated session authorizes a particular onchain action. A public dashboard, assigned view-only access, a manager role, and an executor session are not interchangeable. The [permissions matrix](/operate/permissions) separates these checks.
