# Superform Docs

> Documentation for SuperVaults: ERC-7540 vaults on Base with Merkle-verified execution and validator-secured price-per-share.

## Notes for LLM Agents

- All SuperVaults covered here are on Base (chain ID 8453) unless otherwise stated.
- Persephone API base URL: `https://persephone.superform.xyz/v1` — fully public, no API key required for any endpoint.
- Bundler API base URL: `https://bundler.superform.xyz/` — fully public, no API key required.
- Primary vault discovery: `GET /v1/supervaults?chain_id=8453` — returns all live SuperVaults with APY, TVL, rewards, availability.
- `vault_type: "SUPERVAULT"` is required on all bundler calls for v2 vaults (`is_supervault_v_2: true`).
- Non-smart-account deposit (EOA / Safe / Fireblocks / custodian): `POST /hooks/suggest/non-smart-account` — returns an ordered, variable-length `executions[]` array. Broadcast every returned execution in order; approvals depend on the request and current allowance.
- Redemption is async (ERC-7540): `REDEEM` → poll `maxWithdraw(account)` onchain → `REDEEM_CLAIM`.
- **`maxWithdraw(account)` returns `0` until the keeper fulfills the request.** This is non-standard ERC-4626 behavior. Do not interpret `0` as "no position" — poll `pendingRedeemRequest(0, account)` to confirm the request is queued.
- APY fields: `apy_snapshot_week` and `reward_rate` are both in **percentage points** (e.g. `18.29` = 18.29%). A value of `-1000000` is the no-data sentinel — treat as 0.
- Total APY = `apy_snapshot_week + reward_rate`. Read both current components; their relative contribution varies by vault and observation time.
- bStock token decimals: 8. USDC: 6. WETH: 18. cbBTC: 8.
- Bundler validates on-chain balance before building calldata. Check balance with `GET /v1/balances/{address}` first.
- Bundler errors are deterministic. Fix the request before retrying.
- The `-1000000` sentinel appears when a vault has insufficient PPS history for the requested window (e.g. newly launched vaults).

## Operate notes for LLM agents

- Operate browser requests use same-origin session-mediated BFF routes. Do not extract browser tokens or reuse server-side service credentials.
- Anonymous Strategy reads use a public-vault allowlist. Events, engine telemetry, simulation, and writes are separate authenticated surfaces.
- Strategy/OMS vault IDs use `chainId_vaultAddress`. Management pause-status tuples are a separate colon-delimited format.
- Engine rules are offchain policy; hook roots and contract checks are onchain authorization. Saving a strategy is not signing a hook-root update or starting execution.
- Current plans use `execution_params.strategy_address` and `execution_params.plan.steps`. Input units depend on the first action: assets, shares, and debt tokens are not interchangeable.
- Simulation admission and synthetic outcomes are not proof of real execution or post-action debt reduction. Reconcile intent, execution, receipt, and positions separately.
- UP upkeep, native execution gas, and portfolio liquidity are distinct readiness checks. Config/strategy counts and active flags do not prove execution readiness.
- This index and the full corpus are generated from docs.json. External OpenAPI navigation entries link to their contract; they are not embedded local MDX pages.
