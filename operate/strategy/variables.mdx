## Inspect values before writing a rule

The engine evaluates raw snapshot numbers. Authorized shard-state responses expose `fields` as `{raw, scale}`; human display is `raw × 10^-scale`. A display conversion does not change expression input units. The editor's Copy operation emits the normalized engine expression, which can include decimal divisors.

Use the editor's variable catalog and authorized shard state for the selected vault. Upstream routes are `GET /api/v1/indicators/catalog` and `GET /api/v1/engine/shards/{vault_id}/state`; these are not promises of anonymous access. The OS browser uses the session-mediated Strategy BFF. Public definitions reveal aliases, but not necessarily their current values. Historical intent snapshots are not live balances.

Vault IDs use chain ID, an underscore, and vault address. The [dated carry example](/operate/playbooks/carry#captured-configuration) supplies the superNVDA mapping. Do not reuse its position ID for another Spoke, reserve pair, owner, or chain.

Debt and collateral values are comparable within the same provider's risk-reference convention. Their ratio is LTV; neither is a token amount. Do not assume every reference value is USD. `vault_free_assets` in this NVDAc-denominated vault is not idle USDC.

## Asset/share conversion

For human PPS `P`, asset decimals `a`, and share decimals `s`:

- Asset raw → share raw: `asset_raw × 10^(s-a) / P`.
- Share raw → asset raw: `share_raw × P / 10^(s-a)`.

Clearstar uses 18-decimal shares and six-decimal USDC, so the factor is `10^(18-6) = 1e12`. With synthetic PPS 1.25, two USDC (`2000000` raw) converts to `1600000000000000000` raw shares:

```text
2000000 * 1e12 / 1.25
```

This factor is specific to that pair. Intent sizing truncates toward zero. A redemption hook consumes shares; a repayment hook consumes debt tokens. Use metadata and [plan effects](/operate/strategy/action-config), not a universal “size is assets” assumption.

## Rate and analytics conventions

- **Analytics APY:** `ys_0x91c056b6d4311a743614fbc03ac32d4e6a2d3a3c_apy` is the concrete alias shape for the case-study source; its presence/value must be checked, not inferred from the source's existence. The adapter copies opportunity `apy`, `baseApy`, and `rewardApy` without conversion. The model explicitly interprets APY as **annual percentage points** and accrues `amount × (APY / 100) × elapsed / year`; it is not evidence of a provider's compounding methodology. Do not add reward APY to an `apy` that already includes rewards. The current-opportunity schema has no lookback or provider observation timestamp. Its historical fallback can copy an old APY/TVL point into a newly timestamped feed update. An updated shard is therefore **not proof of current yield**.
- **Position rates:** for example, `position_0xacaa6ee9de7631b927242d42fb8c256860545fa457560f550b653a925bc6cb3b_borrow_rate_e18` has display scale 18. Raw `50000000000000000` displays as ratio `0.05`; it means 5% **only for the provider's stated period**, not necessarily annual APY. The position client parses upstream `borrow_rate`/`supply_rate` integer strings without annualizing. Neither position response nor engine alias encodes rate period, compounding, or APR/APY type. Omitted optional rates stay absent, not verified zero. No live Aave V4 rate-period contract was established by this capture.
- **Resolve the provider boundary before a spread rule:** inspect the authorized position row's `provider`, `protocol_address`, `market_label`, reserve bindings, and `observed_at`. Ask the pricing/feed operator for that exact provider/reserve's rate definition (period, APR or APY, scale, observation block) and the analytics operator for the matched opportunity's `source`, `chain`, `address`, base/reward inclusion, lookback, observation time, and TVL currency. Compare like annualized notionals only after those records agree. If those metadata are unavailable, leave spread-dependent entry inactive; do not guess a multiplier or substitute the dashboard APY.

## Availability, freshness, and inspection

Use **Strategy → the selected definition → variable/state inspection** under an authorized browser session. The upstream shard route above returns `fields`, `positions`, `yield_source_allocations`, `yield_source_liquidity`, and per-strategy `last_eval_at`/`last_signal`. It does **not** expose a universal per-field timestamp, feed-ready flag, or indicator-ready endpoint. A current `last_eval_at` is evaluation time, not the age of every input.

| Family | What the curator can inspect | Availability / freshness boundary and concrete next check |
|---|---|---|
| Vault PPS, supply, total assets, free assets and queue | Exact aliases in `fields`; raw/scale; pending requests and underlying balance via authorized reads | Internal `TrackedField.UpdatedAt` and feed-cycle readiness are not serialized in `fields`. Obtain the subgraph/queue poll timestamp and indexed block from the engine/feed operator when freshness matters; compare onchain state at a named block. Missing evaluator fields can look like zero. |
| Token/native balances | `token_0x833589fcd6edb6e08f4c7c32d4f71b54bda02913_amount`, `native_amount`; compare strategy `balanceOf`/native balance at a named block | Token RPC failure retains the last-known value. Field presence is not a successful latest poll. Ask for token/native feed last successful poll and failure status; do not treat a missing field as an empty wallet. |
| Position amounts, risk, capacity, health and rates | `positions[]`: `position_id`, `provider`, `protocol_address`, token `amount`/`decimals`, `block_number`, `block_hash`, `observed_at`, optional `stale`/`retired`, and optional rate/health values | All belong to a pinned-block generation. An incomplete poll retains prior data and marks it stale; optional omissions remain absent. Compare block/observation and require non-stale matching identity. Ask the position-feed operator for configured maximum age if it is not visible. A retired zero position is not an active zero-debt loan. |
| Source allocation assets/shares | `fields` and `yield_source_allocations[]`; Clearstar `_amount`/`_shares` above | Raw source assets/shares, not USD. Allocation rows omit zero-valued optional properties, so inspect `fields` plus source contract balances. Poll provenance is not exposed in the allocation row; obtain balance-feed block/time before sizing. |
| Source PPS | Clearstar `_pps` in `fields`; source/oracle selection in the plan | FairPrice ingest uses producer `observed_at` and optional `valid_until`, plus configured `FairPriceMaxAge`; receipt time is not source age. Missing/future/expired observations fail admission. These PPS provenance fields are **not forwarded by this shard allocation projection**: ask the feed operator for the matched FairPrice observation/deadline and configured age bound. Zero is never a valid divisor. |
| Asset/share exit liquidity | `yield_source_liquidity[]`: `address`, `asset_address`, `status`, `shares_status`, `collected_at`, `valid_until`, `shares_valid_until`; values in `_liquidity` and `_liquidity_shares` | Inspect asset and share status separately. Missing asset decimals can prevent asset liquidity even when a share observation exists. Require usable, unexpired observations for the exact source/asset; never substitute TVL. |
| APY/base/reward APY and analytics TVL | `yield_source_allocations[]` and corresponding `fields` aliases | Zero properties may be omitted; analytics defaults and absence are not proof of zero yield. Ask for the matched opportunity/history timestamp and source conventions above. Feed-cycle readiness does not reject an old historical APY merely because it is old. |
| Token/market prices | `token_0x833589fcd6edb6e08f4c7c32d4f71b54bda02913_price_usd` for USD quotes; `price` for the configured market track | Positive quotes and configured observation-age checks are required. Price provenance is not attached to every shard field. Obtain the provider observation time and configured quote maximum age from the price-feed operator. Do not infer market hours or price freshness from chain activity. |
| Volume / maturity | Selected indicator `params.field`, `maturity_unix`, configured tick inputs | Volume has no universal currency, interval, or availability guarantee; require the producer's contract. Maturity uses Unix seconds and floors remaining days at zero. Missing required track input is not a ready zero series. |
| In-flight counts | `vault_inflight_request_count`, source count, and shard tracked/occupying intent counts; verify actual OMS/source requests | Counts are derived workload, not amounts or guaranteed arrival. Inspect request ID, phase, claimability and last event time for settlement readiness. |
| Indicators | Saved `indicators` configuration, catalog outputs, dependency fields and historical intent snapshot when present | Internal `Ready()` gates evaluation; no universal ready boolean is exposed by this shard response. Ask the engine operator for warmup/root-input diagnostics using strategy ID/version and alias. Zero output does not establish readiness. |
| Clock | `tick_unix`, `tick_unix_ms`, UTC calendar fields | Evaluation clock, not feed freshness; no `tick_age_seconds` alias. |

Referenced dependencies must have been observed and satisfy the configured feed warmup. Positions, PPS, liquidity and price quotes add their own freshness checks; this is **not a uniform maximum-age guarantee for every balance or analytics field**. `risk_params.eval_max_staleness_ms` checks evaluation age, not upstream observation age. If the authorized response omits the provenance needed for a consequential decision, obtain it from the named feed operator; do not extract browser credentials or invent an inspection API.

## Reusable calculations

The inspected backend persists `indicators: [{name, params, alias}]`, rules, and size expressions. `StrategyConfig` does not expose a generic persisted `custom_variables` expression map. Use registered indicator aliases with catalog parameters, or repeat an explicit subexpression. Shorthand such as `D`, `C`, or `repay_needed` is not executable unless it is an actual configured output.

Derived expressions and indicator outputs are not durable “keep unwinding” state. A threshold becoming false stops a stateless rule even if debt remains.

### Verified indicator serialization

The engine's `TestDeriveRequiredSnapshotKeys_IndicatorAliasUsesRootPPS` configures this indicator: `{"name":"sma","alias":"smooth_pps","params":{"window_ms":1000,"field":"ys_0xe8dd6a1e13244a27bdaa19ccbf33013647c675d1_pps"}}`. It is an **actual source-test configuration**, not a claim that the dated NVDAc strategies use indicators (their captured arrays are empty). Store it as an entry in `indicators`, not in a `custom_variables` map. In the editor select the catalog's `sma`, its `field`, a `window_ms` of `1000`, and alias `smooth_pps`; the field must resolve for the selected vault before authoring against it.

`smooth_pps` is the executable single-output alias; the test's rule is `smooth_pps > 0.9`. The value is the sample mean of the human PPS track, so it remains assets per share, not a token amount or annual yield. A one-second window is milliseconds, **not one sample**: readiness requires at least two retained samples and window coverage (including the implementation's aged-out anchor). The engine follows the indicator's root PPS dependency for freshness; an indicator alias does not bypass PPS admission. Multi-output indicators use `alias_output` such as MACD's `_histogram`, and chained parameters use `from` plus the catalog's `from_output` rather than inventing an expression variable.

Indicator tracks use float64. Do not use a smoothed raw 18-decimal balance as an exact integer sizing substitute; values above `2^53` can lose precision. Inspect catalog outputs, saved parameters, and root-feed evidence, then test the actual graph's warmup and rule before activation.
