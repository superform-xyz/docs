## Delivery is not an execution ledger

Configured channels route operational alerts to selected destinations. Use authorized settings to manage a channel and bind it to a vault. Channel CRUD/binding does not prove every proposed alert category is emitted or establish a generic public webhook API.

Review supported delivery types, ownership, binding, and enabled event coverage. Keep destination secrets server-side. Do not send an unsolicited test notification while inspecting configuration.

Upstream routes include `/api/v1/notification-channels` and `/api/v1/vaults/{chain_id}/{vault_address}/notification-channels`. These are authenticated management surfaces, not anonymous automation endpoints. See [Access and API boundaries](/operate/authentication).

## Audit contract

Source-reviewed `GET /api/v1/audit/logs` supports `limit`, `offset`, `start_time`, `end_time`, `action`, `resource_type`, `resource_id`, `actor`, `status`, and `correlation_id`. Rows include `id`, `created_at`, `action`, `resource_type`, `resource_id`, `actor`, `status`, `details`, and `correlation_id`.

Do not copy older `from_timestamp`, `to_timestamp`, `action_type`, or `actor_wallet` examples. The handler returns a log array to the response layer; verify the deployed envelope in your approved adapter instead of assuming a `logs`/`has_more` object. A resource-ID filter is not a universal vault filter for every resource type.

The repository orders by `created_at DESC`, with offset pagination and inclusive time bounds. There is no stable timestamp-plus-ID cursor or snapshot across pages. Offset polling cannot guarantee lossless or exactly-once ingestion under concurrent inserts or equal-timestamp ordering.

## Bounded polling core

Supply `fetch_page(params)` from an approved integration. It must validate/unwrap the response to a list, enforce HTTP timeouts, and raise on access, network, or schema errors. Supply durable processed IDs. This core sends no notifications and does not advance durable state itself.

```python
from datetime import datetime, timedelta

def collect_audit_window(fetch_page, watermark, end_time, seen_ids,
                         overlap_seconds=300, page_size=100, max_pages=1000):
    if watermark.tzinfo is None or end_time.tzinfo is None:
        raise ValueError("aware timestamps required")
    if end_time < watermark or page_size < 1 or max_pages < 1:
        raise ValueError("invalid window or pagination bounds")
    if overlap_seconds < 0:
        raise ValueError("negative overlap")
    start = watermark - timedelta(seconds=overlap_seconds)
    high = watermark
    pending = {}
    for page in range(max_pages):
        rows = fetch_page({
            "start_time": start.isoformat(),
            "end_time": end_time.isoformat(),
            "limit": page_size,
            "offset": page * page_size,
        })
        if not isinstance(rows, list) or len(rows) > page_size:
            raise ValueError("invalid audit page")
        for row in rows:
            event_id = row["id"]
            stamp = datetime.fromisoformat(row["created_at"].replace("Z", "+00:00"))
            if not isinstance(event_id, str) or not event_id or stamp.tzinfo is None:
                raise ValueError("invalid event identity or time")
            if not start <= stamp <= end_time:
                raise ValueError("event outside requested window")
            high = max(high, stamp)
            if event_id not in seen_ids:
                pending[event_id] = row
        if len(rows) < page_size:
            ordered = sorted(pending.values(), key=lambda r: (r["created_at"], r["id"]))
            return ordered, high
    raise RuntimeError("page bound reached; watermark must not advance")
```

Fix `end_time` for the whole cycle, preferably behind current time by an ingestion-lag allowance. The returned watermark is the maximum **observed event time**, not local wall-clock time. An empty window leaves it unchanged. Overlap and ID deduplication allow repeated boundary events and ordinary delayed arrivals without duplicate processing.

Persist rows, deduplication IDs, downstream outbox entries, and the returned watermark atomically only after the complete cycle succeeds. On any page/processing failure, retain the old checkpoint and retry idempotently. Never advance after page one just because newer events were visible there.

A finite overlap does not protect against arbitrary late insertion. Periodically replay a larger range and compare with authoritative exports/state. Equal-timestamp offset instability and rows inserted behind the overlap remain limitations. If lossless ingestion is required, obtain a stable-cursor/snapshot contract rather than labeling this core production-complete.

## Separate event families

| Need | Evidence |
|---|---|
| Manager/configuration actions | Authorized audit records |
| Current readiness | Current vault, engine, and service observations |
| Intent lifecycle | Intent detail plus authorized OMS events |
| Settlement | Fills, receipts, and position reconciliation |
| Human alerts | Configured channel delivery evidence |

Missing audit data does not prove no transaction occurred, and notification delivery does not prove settlement. Use [Intent History](/operate/ui/intent-history) and [Monitoring](/operate/automation/monitoring).
