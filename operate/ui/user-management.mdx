## Select the vault

Open **User Management** in authenticated Operate and verify chain, vault address, and connected wallet. The public Roles tab is read-only. Session authentication does not itself grant access to a vault.

| Action | Required management role | Change type |
|---|---|---|
| Add/remove Secondary Manager | Primary Manager | Prepared onchain transaction |
| Add/remove view-only user | Primary or Secondary Manager | Offchain assignment |
| Update user display name | Primary or Secondary Manager | Offchain metadata |
| Replace Primary Manager | Separate contract recovery/governance path | Not an ordinary edit in this tab |

## Secondary Managers

Choose **Add Secondary Manager**, enter the verified wallet address, and prepare the transaction. Inspect chain, strategy, target wallet, and decoded operation before signing. For removal, prepare and sign the removal transaction. After confirmation, read the manager list and onchain membership again.

A Secondary Manager has delegated operational powers, not unrestricted access to primary-only settings. Removing a manager is not the same as revoking every session that may have been granted previously; review [Execution accounts](/operate/ui/execution-accounts) during an access change.

## View-only users and display names

Either manager can add or remove an offchain view-only assignment. The assigned user must authenticate to inspect private rules. View-only users cannot save, start, or simulate strategies.

Display names help identify wallets but are not authority. Verify addresses independently before granting access; read the assignment back after each change.

## Primary Manager

The Primary Manager tab displays the current main manager. The Aggregator supports a `SUPER_GOVERNOR` replacement path and a separate Secondary-Manager-initiated timelocked proposal path. It is not immutable or governance-only. Review [Access and roles](/operate/permissions) and the current contract state before an approved recovery procedure.

## Management API contracts

These upstream paths are mediated by the browser BFF; they are not standalone credential instructions.

| Method | Path | Operation |
|---|---|---|
| GET | `/api/v1/users` | List users, scoped by `chain_id` and `vault_address`; paginate the result |
| POST | `/api/v1/users/secondary-manager/prepare` | Prepare add-manager transaction |
| POST | `/api/v1/users/secondary-manager/remove/prepare` | Prepare remove-manager transaction |
| POST | `/api/v1/users/view-only` | Add view-only assignment |
| DELETE | `/api/v1/users/view-only/{wallet}` | Remove assignment with vault/chain context |
| PATCH | `/api/v1/users/{wallet}/display-name` | Update offchain name with vault/chain context |

If a role change appears stale, refresh the user session and selected-vault data. Do not retry grants until the transaction receipt and current membership have been checked.
