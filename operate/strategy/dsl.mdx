## Rule trees

Each strategy has one boolean `rules` tree. Action sizing is a separate numeric expression.

| Node | Required fields | Evaluation |
|---|---|---|
| `EXPR` | `expr` | Boolean expression, not numeric truthiness |
| `AND` | `children`, at least two | All pass; short-circuits in order |
| `OR` | `children`, at least two | Any passes; short-circuits in order |
| `NOT` | `children`, exactly one | Negates that child |
| `VOTE` | `children`, `threshold` | Requires `ceil(threshold × child count)` passes |

`VOTE.threshold` is a fraction greater than zero and at most one. The following tree requires two of three children, not one:

```json
{
  "type": "VOTE",
  "threshold": 0.5,
  "children": [
    {"type": "EXPR", "expr": "true"},
    {"type": "EXPR", "expr": "false"},
    {"type": "EXPR", "expr": "true"}
  ]
}
```

`NOT` has no singular `child` field:

```json
{"type": "NOT", "children": [{"type": "EXPR", "expr": "false"}]}
```

## Expression grammar

| Operation | Syntax |
|---|---|
| Arithmetic | `+`, `-`, `*`, `/`, parentheses, scientific notation such as `1e12` |
| Comparison | `>`, `>=`, `<`, `<=`, `==`, `!=` |
| Boolean | `&&`, `||`, `!`, `true`, `false` |
| Numeric functions | `min(a, b)`, `max(a, b)`, `abs(a)`, `clamp01(a)` |

`min` and `max` take exactly two arguments. Nest them for additional caps. There is no `floor`, `pow`, ternary operator, assignment, or arbitrary JavaScript execution.

```text
min(3, max(1, 2))
```

The result is `2`. Numbers use the engine's high-precision expression VM. Positive action sizes are truncated toward zero when converted to integer intent amounts; a positive fraction below one raw unit does not create a usable amount. See [Sizing and execution plans](/operate/strategy/action-config).

## Guard runtime division

Prefer multiplication for ratio triggers:

```json
{
  "type": "EXPR",
  "expr": "vault_tvl > 0 && vault_free_assets > 0.10 * vault_tvl"
}
```

If division is necessary, place its guard first:

```json
{
  "type": "EXPR",
  "expr": "vault_tvl > 0 && vault_free_assets / vault_tvl > 0.10"
}
```

Both are false for an empty snapshot without dividing by zero. `AND`/`OR` tree order matters for the same reason. Do not rely on a guard in a different strategy. A `VOTE` tree is not a substitute for an outer safety guard.

## Validation stages

1. **Editor:** quantity, token metadata, action parameters, and expression checks help construct a payload. Copy the normalized engine expression to inspect its actual units.
2. **Save:** backend shape, identifier-policy, and static-type checks reject malformed trees, unknown aliases, and boolean/numeric type mismatches. This is not an empty-snapshot execution.
3. **Evaluation:** the compiled expression reads a snapshot. Missing identifiers read as zero at this low-level stage; division can still fail at runtime.
4. **Publication:** readiness, freshness, positive integer size, conviction, risk, cooldown, and occupied-slot checks can prevent an intent even when its boolean rule is true.
5. **Execution:** authorization, available balances, venue constraints, slippage, and transaction success are separate checks.

A syntactically valid dynamic identifier is not proof that a feed supplies it. Use [Variables and units](/operate/strategy/variables), not invented aliases such as `vault_pps_stale`, `tick_age_seconds`, or `ys_<address>_alloc`.

## Conviction

```json
{"mode": "BINARY"}
```

| Mode | Current-evaluation score |
|---|---|
| `BINARY` | One when the rule fires, zero otherwise |
| `RULE_VOTE_RATIO` | Fraction of passing top-level children |
| `INDICATOR_DISTANCE` | Absolute indicator distance divided by configured scale, clamped to the allowed range |
| `EXPR` | Numeric expression clamped to `[0, 1]` |

Minimum conviction can suppress publication. These modes do **not** count consecutive passing ticks. `RULE_VOTE_RATIO` evaluates top-level children independently, so a separate top-level guard does not protect another child's division while calculating that score. Make each child safe or use `BINARY` for a guarded trigger.
