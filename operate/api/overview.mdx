## Service map

| Service | Owns | Browser BFF prefix |
|---|---|---|
| [Erebor](/operate/api/erebor) | Management, registries, settings, upkeep, users, hooks, notifications | `/api/erebor` |
| [Strategy Engine](/operate/api/strategy) | Definitions, lifecycle, simulations, publication, intent projections | `/api/strategy` |
| [OMS](/operate/api/oms) | Intent execution, events, session readiness and rotation | `/api/oms` |

Paths in service tables are **upstream paths**. For example, the browser routes upstream `/api/v1/strategies` through `/api/strategy/api/v1/strategies`. A service inventory does not mean every endpoint is publicly accessible or supported for a third-party writer.

## Access classes

| Class | Supported use | Boundary |
|---|---|---|
| Public read | Discovery, published artifacts, allowlisted vault-scoped Strategy GETs | Vault publicness, method, query, and ownership checks still apply |
| Authenticated browser | Operate with the shared account session and selected vault role | BFF resolves session and performs role checks; upstream credentials remain server-side |
| Approved programmatic integration | Explicitly onboarded service access | Obtain endpoint, credential mechanism, scope, rotation, and rate limits from the team |
| Internal service/control surface | Engine telemetry, direct execution, infrastructure controls | Not a public curator API merely because a schema exists |

Do not extract browser cookies or tokens to build an integration. [Authentication](/operate/authentication) describes the supported account flow. The public Persephone/Bundler APIs documented under [Build](/build) are separate from curator management access.

## Read, mutate, prepare, execute

- **Read:** inspect a definition, balance, session, or recorded event. Some GET endpoints prepare session transactions and are manager-gated, not passive public reads.
- **Offchain mutation:** save a strategy, set redemption timing, change service control, or attach a notification channel. These can change behavior without a wallet transaction.
- **Prepare:** return calldata for an authorized signer. Success does not mean protocol state changed.
- **Execute and verify:** obtain the receipt for a signed transaction, then refresh the affected contract and API state. Do not confuse indexing success with the intended economic outcome.

## Identity and versions

Use chain plus vault address as identity. Strategy/OMS vault IDs use `chainId_vaultAddress`; do not substitute the colon-separated tuple used by management pause-status queries. Strategy updates and lifecycle transitions carry optimistic versions. On conflict, fetch current state and review differences rather than blindly replaying a write.

The management and OMS repositories contain OpenAPI contracts; the Strategy repository also contains its API schema. References here are source-reviewed inventories, not a guarantee that each service exposes a public, maintained schema URL or that a deployed binary matches the inspected source. Authenticated rehearsal and transaction execution require separate authorization.
