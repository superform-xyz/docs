## SuperStocks coverage

| Definition | Supported check | Limit |
|---|---|---|
| AP0 / AF0 idle-USDC repayment | Admitted by simulation validation | No Aave repayment feedback proving debt reduction or post-action LTV |
| AP1 / AF2 redeem-then-repay | Not admitted with their liquidity guards | Asset/share liquidity observations are unsupported by replay |
| Source allocation deposit/withdrawal | Modeled allocation changes | Synthetic fills, not venue execution |

AP1/AF2 return `liquidity observations are not supported by simulation replay`. **Keep the liquidity guards.** Removing them changes the strategy, not the simulator's coverage.

For the [AP0 writing example](/operate/strategy/quickstart), check the rule boundaries and raw size separately. A successful model run does not prove the position reached 50% LTV. Look Ahead seeds token balances/prices at initialization; it does not evolve a complete debt/collateral market.

## Run a supported simulation

1. Open **Simulation** with the intended vault selected.
2. Choose **Backtest** with **From / To**, or **Look Ahead** with **Horizon (hours)** and **Seed Price (optional)**.
3. Review the selected strategies. The UI initially selects loaded definitions; select only the saved IDs you intend to compare.
4. Review **Execution Model**: **Fill Ratio**, **Slippage (bps)**, **Reject Prob**, **Fail Prob**, **Min Latency (ms)**, and **Max Latency (ms)**.
5. Choose **Run Backtest** or **Run Forward Simulation** with manager authority.
6. Inspect charts, **Simulation Outcomes**, per-strategy results, and **Commands**. Compare trigger timing and integer amounts, not just totals.

Selected `CREATED` and `IDLE` strategies are loaded as running **in the model**, without changing their production state. Do not activate a live strategy merely to make it selectable. Requests select persisted `strategy_ids`, not an arbitrary unsaved expression and snapshot.

Backtests depend on available history and model seeding. Missing history can use PPS fallback seeding. Record the input window and assumptions; zero commands alone is not proof of correctness.

## Save and compare results

Choose **Save Simulation** to retain a named result or **Discard** to clear it. **Existing simulation found. Running will load cached results.** means **Load Existing Result** is loading a cache, not computing a fresh run.

When comparing an update, retain the strategy ID/version, rule, size, selected scope, time range, model settings, and whether results were cached. A saved result describes that configuration, not the current live vault.

## What each check establishes

| Check | Establishes |
|---|---|
| Editor and save validation | Expression structure, allowed identifiers, types, and plan schema |
| Evaluator cases | Rule and size behavior on supplied snapshots, including boundaries and caps |
| Backtest / Look Ahead | Commands and synthetic outcomes for supported inputs |
| Transaction preflight | Feasibility under the chosen transaction state |
| Receipt and position reconciliation | What a particular execution actually changed |

Before activation, test zero/missing debt and collateral, exact trigger edges, insufficient funds, and integer truncation. Check fresh data, authorization, and execution readiness separately. After deliberate activation, follow [Intent History](/operate/ui/intent-history).

## API reference

| Endpoint | Purpose |
|---|---|
| `POST /api/v1/simulations/backtest` | Historical simulation |
| `POST /api/v1/simulations/ahead` | Forward simulation |
| `GET /api/v1/simulations/saved` | List saved results |
| `GET /api/v1/simulations/saved/{simulation_id}` | Read a saved result |
| `POST /api/v1/simulations/saved/lookup` | Look for an equivalent result |
| `POST /api/v1/simulations/saved` | Save a result |
| `DELETE /api/v1/simulations/saved/{simulation_id}` | Delete a saved result |
