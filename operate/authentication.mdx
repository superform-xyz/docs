## Browser access

1. Open [SuperformOS](https://os.superform.xyz) and choose **Connect**.
2. Complete the shared Superform account flow. If prompted, review **Accept the Superform terms** and choose **Accept and continue** yourself.
3. Open **Operate → My SuperVaults**. Confirm the chain and vault address, then verify the assigned role.
4. Inspect rules with an assigned view-only role, or use manager controls with a Primary or Secondary Manager role.

Authentication is not a manager assignment or a transaction approval. Public Strategy cards can be locked even when public API data is readable; authenticated **View rules** and manager **Manage** are separate UI affordances.

## Browser and upstream boundaries

SuperformOS uses same-origin backend-for-frontend (BFF) routes. The BFF reads the browser session server-side, checks vault access, and forwards requests using the appropriate upstream authentication. Strategy and OMS service credentials stay server-side. Erebor user authentication is forwarded by the server, not supplied by copying a token into a browser script.

| Browser route family | Responsibility |
|---|---|
| `/api/auth/me` | Resolve the current browser session and roles |
| `/api/erebor/api/v1/...` | Management reads and configuration operations |
| `/api/strategy/api/v1/...` | Strategy definitions, lifecycle, simulations, and intent projections |
| `/api/oms/defix/...` | Execution and session-key operations |

An upstream error is not by itself proof that the browser session has expired. Reconnect when the application's session check requires it; inspect service and permission failures separately.

<Warning>
Do not export cookies, extract browser tokens, copy service credentials, or treat a wallet private key as an API key. These docs do not define a generic Dynamic signature-to-token recipe for automation.
</Warning>

## Public reads

The BFF permits a narrow allowlist of anonymous Strategy GET requests after verifying that the referenced vault is public. This includes vault-scoped strategy and intent lists, intent detail and fills. It does not include intent events, arbitrary engine state, simulation requests, or writes. Unknown query keys and unbound identity filters can be rejected.

Public discovery and published proof artifacts have their own management API policies. Do not infer that every GET is public, or that a public read grants a write role. See [Strategy API](/operate/api/strategy).

## Programmatic access

Use public read routes where documented. For authenticated automation, obtain an approved endpoint, identity mechanism, role scope, credential lifecycle, and rate policy from the Superform team. Upstream service credentials are infrastructure credentials, not self-service curator credentials.

A successful browser login does not establish that a headless writer is supported. Keep automation read-only until its identity and permissions have been agreed and tested in a separately authorized environment.
