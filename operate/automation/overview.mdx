## Access before automation

Use public reads for public data. Authenticated writers require an approved integration endpoint, identity mechanism, vault/operation scope, credential lifecycle, and rate policy. A browser session or an upstream service schema is not a self-service automation credential. See [Authentication](/operate/authentication) and [API boundaries](/operate/api/overview).

Keep infrastructure credentials server-side. Do not export browser cookies, reuse service keys in client code, or invent a wallet-signature exchange. Store approved integration credentials in the deployment's secret manager and redact them from logs.

## Read before write

1. Fetch current chain/vault identity, definition version, lifecycle state, role, and relevant balances.
2. Validate the proposed operation and its denomination. Check source whitelist, hook authorization, funding, session, freshness, and liquidity.
3. Record the intended change and require the appropriate approval. Use an explicitly authorized isolated environment for tests; Base mainnet is not a sandbox.
4. Apply only the approved mutation. Offchain Save, lifecycle transitions, service pause, and settings changes can have real consequences without a signature prompt.
5. Read back the exact target. For signed changes, verify the receipt and resulting contract state as well as the API projection.

On optimistic-version conflict, fetch and compare before retrying. On a timeout after a write, inspect current state before repeating it. Do not assume a timed-out request did nothing.

## Polling and failure policy

- Set request timeouts and bounded backoff; separate authentication failure, permission denial, rate limiting, invalid request, and unavailable service.
- Treat missing or stale telemetry as unknown. Never substitute a healthy balance, PPS lifetime, or success rate.
- Paginate a fixed event window and persist a watermark with overlap and ID deduplication. Do not advance to local wall-clock time after one page.
- Keep monitoring separate from remediation. An alert must not start a production strategy or submit a repayment unless that action has explicit authority and tested limits.
- Preserve intent, execution, transaction, and configuration-version identifiers for reconciliation; redact credentials and confidential account metadata.

[Monitoring](/operate/automation/monitoring) defines observations and [Notifications and audit polling](/operate/automation/webhooks) explains delivery and cursor handling. [Pause and recovery](/operate/ui/pause) distinguishes service control, contract pause, and target-specific exit.

## Verification ladder

Editor validation and backend static validation check definitions. Evaluator fixtures check logic and units. Supported model replay checks modeled behavior, not real OMS execution. Transaction preflight and receipt/position reconciliation are separate checks in an authorized environment. Keep these results distinct in automation logs and approval records.
