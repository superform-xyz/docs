description: "Match the size to the first hook and carry actual outputs between execution steps."

`rules` decides whether to act. `action_config.size_expr` sizes the first input. `execution_params.plan.steps` specifies the ordered hooks and how amounts pass between them. Use the registry-backed editor to build the plan.

## Action fields

| Field | Meaning |
|---|---|
| `action` | Action enum, such as `DEPOSIT`, `WITHDRAWAL`, or `REBALANCE` |
| `size_expr` | Numeric expression converted to integer raw input units |
| `objective` | `BALANCED`, `MIN_SLIPPAGE`, or `MIN_TIME` |
| `from_address` | Vault/account context, not necessarily the token-holding strategy |
| `target_address`, `target_type` | Target and canonical family, such as `ERC4626` or `VAULT` |
| `execution_params.strategy_address` | Execution strategy contract |
| `execution_params.plan.steps` | Ordered hook metadata and parameters |
| `max_slippage_bps` | End-to-end slippage budget; positive when the plan consumes one |
| `max_duration_seconds` | Execution deadline policy; deferred plans have additional requirements |

Legacy top-level `execution_name` and `execution_address` do not describe the current plan contract. Each step has its own hook name, address, effect metadata, arguments, and `use_prev_hook_amount` setting. Do not combine one source's encoded arguments with another source or oracle.

## Input units

| First hook | Size unit |
|---|---|
| ERC-4626 deposit | Raw underlying assets |
| ERC-4626 redeem | Raw source shares |
| Aave V4 borrow or repay | Raw debt tokens |
| Aave V4 collateral withdrawal | Raw collateral tokens |

The size is **not universally the SuperVault underlying**. In the [superNVDA example](/operate/strategy/quickstart), repayment consumes 6-decimal USDC; NVDAc has 8 decimals, while the Clearstar source shares have 18.

The engine truncates positive sizes toward zero when constructing an integer intent amount. A positive fraction below one raw unit is not usable. Cap by the available input balance, debt or holdings as applicable, and observed exit liquidity. Test integer boundaries with the evaluated expression, not just a decimal calculator.

## Multiple execution steps

For **borrow → deposit**, the first step sizes raw USDC to borrow. A following `ApproveAndDeposit4626VaultHook` with `use_prev_hook_amount: true` deposits the USDC actually received, not a separately assumed amount.

For **redeem → repay**, `Redeem4626VaultHook` first consumes raw source shares. A following `AaveV4RepayHookV2` with `use_prev_hook_amount: true` consumes actual redeemed USDC. Do not send the share count to repayment. The size must convert the desired assets to shares through positive PPS and decimal scaling, then respect holdings and both asset/share exit liquidity.

Same-chain immediate steps can execute as a bundled hook transaction. That does not make separate canvas cards a transaction sequence, or make deferred and cross-chain plans atomic. See the recorded [AP1 fill](/operate/ui/intent-history#a-recorded-superstocks-execution).

## Before activation

- Check the first input's token, denomination, account balance, and amount caps.
- Verify the selected source, oracle, position binding, and active hook authorization.
- Review slippage, deadline, session readiness, gas, and competing spenders.
- Confirm each later step consumes the intended previous output.
- After execution, reconcile token flows and position changes, not only the intent status.
