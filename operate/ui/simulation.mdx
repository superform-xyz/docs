## Coverage before running

| Mechanism | Establishes | Does not establish |
|---|---|---|
| Editor checks | Expression/quantity structure, required parameters, metadata readiness | Behavior on arbitrary snapshots or transaction success |
| Backend save validation | Rule shape, allowed identifiers, static types, plan schema | Empty-snapshot execution or usable live data |
| Actual evaluator fixtures | Rule and size behavior for supplied synthetic snapshots | Production freshness gates, balances, permissions, or fills |
| Backtest / Look Ahead | Commands and modeled outcomes for supported inputs and selected definitions | A forked transaction or forecast of returns |
| Separately authorized transaction preflight | Transaction feasibility under the chosen state/model | Future settlement or future liquidity |
| Mined receipt and position reconciliation | What a particular execution actually changed | Success of future executions |

## Current carry support

The [2026-10-19 superNVDA definitions](/operate/playbooks/carry#captured-configuration) were checked against the pinned simulator admission validator:

| Definition / input | Admission | Economic coverage |
|---|---|---|
| AP0 / AF0 idle-USDC repayment | Admitted | No implemented Aave repayment feedback proving post-action LTV |
| AP1 / AF2 redeem → repay | Rejected | Referenced asset/share liquidity is unsupported by replay |
| Source allocation deposit/withdrawal | Model has allocation feedback | Synthetic outcomes, not venue execution |
| REBALANCE action | No allocation delta from the publisher model | Not a loan-position transition |
| Look Ahead token balances/prices | Seeded at initialization | Not automatically evolved as a complete debt/collateral market |

The exact AP1/AF2 admission error contains:

```text
liquidity observations are not supported by simulation replay
```

<Warning>
Do not remove production liquidity guards to make a strategy simulate. AP0/AF0 admission is not proof that repayment, debt reduction, liquidation safety, or target LTV has been modeled.
</Warning>

## Run a supported model

1. Open **Simulation** with the intended vault selected.
2. Choose **Backtest** with **From** / **To**, or **Look Ahead** with **Horizon (hours)** and **Seed Price (optional)**. A blank seed uses live price where available.
3. Select only the intended persisted strategy IDs. The UI initially selects loaded strategies; review this rather than assuming isolation.
4. Inspect **Execution Model**: **Fill Ratio**, **Slippage (bps)**, **Reject Prob**, **Fail Prob**, **Min Latency (ms)**, and **Max Latency (ms)**.
5. Choose **Run Backtest** or **Run Forward Simulation**. Running requires manager write authority in the inspected UI.
6. Review charts, **Simulation Outcomes**, per-strategy breakdowns, and **Commands**. Compare exact trigger boundaries and integer amounts, not only totals.

Requests select persisted `strategy_ids`; they do not accept an arbitrary unsaved rule and snapshot. The backend loads selected CREATED/IDLE configurations into RUNNING in memory for the simulation, without updating their production lifecycle. Do not start a live strategy merely to make it selectable.

Backtests depend on available history, source coverage, and model seeding. PPS fallback seeding can be used when history is absent. Record the data window and assumptions alongside the result. Zero commands is not itself proof of either correctness or failure.

## Saved results and caching

Name the result and choose **Save Simulation** to retain it; **Discard** clears the current result. If a matching run exists, the UI says **Existing simulation found. Running will load cached results.** and offers **Load Existing Result**. That is not a fresh computation.

When comparing an edit, retain strategy IDs/versions, rules, sizes, selected scope, input range, execution-model settings, and whether the result was cached. A saved result is evidence for that configuration and model, not the current live vault.

## Evaluator test matrix

Before activation, test at least:

- Normal state and exact trigger boundaries.
- Missing inputs, zero debt/collateral, zero PPS, and zero exit liquidity.
- Insufficient idle funds, one-raw-unit dust, and positive fractions truncated to zero.
- Asset/share conversion and the intended post-action reserve or LTV.
- A partial unwind that disarms while debt remains.
- Cooldown, occupied concurrency slot, and stale-version update.
- Unsupported simulation inputs without deleting their guards.

Local documentation fixtures invoke the actual pinned engine compiler/evaluator and plan validator. They are not a browser test endpoint. See [Troubleshooting](/operate/strategy/troubleshooting) when a strategy saves but does not publish or settle.
