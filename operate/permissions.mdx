## Role boundaries

| Role | Scope |
|---|---|
| Primary Manager | Onchain main manager; primary-only configuration and delegation |
| Secondary Manager | Delegated onchain manager; operational actions within protocol constraints |
| View-only | Offchain vault assignment; authenticated inspection, not execution |
| Registry maintainer | Global metadata maintenance; not automatically a vault manager |
| Executor/session key | Delegated execution authority with explicit validity and scope |

Manager authority does not bypass hook proofs, venue checks, fee limits, pricing constraints, or timelocks. Assets may be held in external positions, not only idle in the vault.

## Operation matrix

The table distinguishes the inspected application/API policy from contract authority. A UI control can be narrower than an API policy; API preparation is not permission to sign as another account.

| Operation | Application or API gate | Transaction boundary |
|---|---|---|
| Inspect public dashboard and allowed history | Public vault and anonymous read allowlist | None |
| Open **View rules** in Operate | Assigned view-only, Primary, or Secondary Manager | None |
| Create/save/reorder/start strategies; run simulation | Primary or Secondary Manager for the selected vault | Offchain mutation; starting can cause later execution |
| Add/remove Secondary Manager | Erebor prepare endpoints: Primary Manager | Aggregator `addSecondaryManager` / `removeSecondaryManager`: main manager |
| Add/remove view-only user; update display name | Erebor: either manager | Offchain mutation |
| Whitelist/remove sources or change paired oracle | Yield Sources UI: Primary Manager; Erebor prepare endpoints: either manager | Check the prepared contract call and signing authority |
| Create/activate hook config; request tree generation | Erebor: either manager | Offchain until root update |
| Propose strategy hook root | Main manager | Signed proposal; execution waits for configured timelock |
| Request proof artifact publication | Erebor: Primary Manager | Artifact publication is separate from root activation |
| Change fee configuration, PPS expiration, deviation threshold, or banned leaves | Erebor settings writes: Primary Manager | Prepared onchain calls; proposal/execute where applicable |
| Propose/cancel minimum PPS update interval | Erebor: Primary Manager | Signed proposal/cancellation |
| Execute matured minimum PPS update interval | Erebor execution preparation: either manager | Contract execution is permissionless after a valid pending proposal's timelock expires |
| Set/delete redemption timing setting | Erebor: Primary Manager | Offchain setting, not a transaction prepare call |
| Prepare Erebor session grant/revoke | Primary Manager | Delegation transaction still requires the authorized signer |
| Pause/unpause vault | Erebor prepare: either manager | Aggregator pause/unpause: either manager |
| Pause/resume per-vault keeper services | Erebor: either manager | Offchain service control |
| Create/attach/detach vault notification channels | Erebor: either manager | Offchain configuration |
| Propose upkeep withdrawal | Primary Manager | Timelocked withdrawal; inspect recipient and execution conditions |

OMS grant/rotation preparation has a separate BFF manager gate and contract signing requirements. Do not infer that access to prepared calldata makes a Secondary Manager eligible to sign every delegated-session change. See [Execution accounts](/operate/ui/execution-accounts).

## Primary Manager replacement

The current Aggregator has two different paths:

- `changePrimaryManager`: privileged `SUPER_GOVERNOR` path.
- `proposeChangePrimaryManager`: a Secondary Manager proposes a replacement and fee recipient; `executeChangePrimaryManager` applies it after the manager-change timelock and contract checks.

The ordinary User Management tab displays the Primary Manager; it is not a replacement wizard. Replacement is neither an unrestricted Secondary Manager edit nor governance-only. Review pending proposals, effective time, and the contract's reset of delegated configuration before using an approved recovery procedure.

## Verification boundary

These gates were checked against application, Erebor policy, and Aggregator source. They do not certify the deployed bytecode or a successful authenticated signing rehearsal. For any mutation, verify the selected vault, current role, prepared call, resulting receipt if applicable, and a fresh readback. [Authentication](/operate/authentication) covers session failures; [User Management](/operate/ui/user-management) covers assignments.
