## Monitor separate layers

| Layer | Inspect | Escalate when |
|---|---|---|
| Accounting | PPS, observation time, idle underlying, supply | PPS expires, observations are unavailable, or accounting cannot be reconciled |
| Carry | Debt/collateral, risk values, rates | Threshold crossed, spread deteriorates, or position data is stale |
| Source | Shares, PPS, asset/share exit liquidity | Repayment or redemption cannot be funded |
| Strategy | Version, lifecycle, readiness, cooldown, slots | Intended RUNNING policy does not evaluate or publish |
| OMS | Session keys, proof coverage, gas, intents, fills | Execution fails, expires, or remains unresolved |
| Redemptions | Queue value/age, requests, claimable assets | Obligations grow without realizable underlying liquidity |
| Service telemetry | Observation time, status, sample coverage | Collection fails, samples are absent, or metrics degrade |

Upkeep funding and execution gas are distinct. A RUNNING definition and a successful last intent do not imply every dependency is ready now.

## Access and collection

Use public GET routes only for fields they expose. The [intent trace](/operate/ui/intent-history) provides copyable public detail/fill requests. Shard state, service telemetry, audit logs, and manager writes have separate [access boundaries](/operate/authentication).

Programmatic monitoring needs an approved integration with a documented endpoint, response schema, and credential scope. Do not extract browser cookies/JWTs or invent a wallet-signature login flow. The example below is local classification logic, not an anonymous service-health API.

Record collection time separately from producer observation time. HTTP success with stale data is not a fresh observation. Avoid overlapping polls, use timeouts/backoff, and retain collection failures rather than replacing them with defaults.

## Unknown-safe classification

The function accepts a normalized record from your verified adapter, not an unverified API payload. `value` is a success ratio in `[0, 1]`; `observed_at` is an aware datetime. Maximum age and alert thresholds are operator policy.

```python
import math
from datetime import datetime

def classify_success_ratio(record, now, max_age_seconds):
    if max_age_seconds <= 0 or now.tzinfo is None:
        raise ValueError("an aware time and positive maximum age are required")
    if not isinstance(record, dict):
        return "UNKNOWN"
    value = record.get("value")
    observed = record.get("observed_at")
    if isinstance(value, bool) or not isinstance(value, (int, float)):
        return "UNKNOWN"
    if not math.isfinite(value) or not 0 <= value <= 1:
        return "UNKNOWN"
    if not isinstance(observed, datetime) or observed.tzinfo is None:
        return "UNKNOWN"
    age = (now - observed).total_seconds()
    if age < 0 or age > max_age_seconds:
        return "UNKNOWN"
    if value < 0.80:
        return "CRITICAL"
    if value < 0.95:
        return "WARNING"
    return "HEALTHY"
```

Tests include absent value/time, NaN, out-of-range values, stale/future timestamps, and exact 0.80/0.95 boundaries. No absent metric defaults to `1.0`. Verify whether the upstream field is a ratio or percentage before normalizing; do not silently clamp an unknown unit.

## Alert policy

Assign thresholds, an owner, and a response per vault/venue. Track independent conditions for:

- PPS near expiry and unavailable PPS.
- Automation risk trigger versus hard venue threshold.
- Insufficient debt tokens or exit liquidity for the repayment objective.
- Growing queue value/age and stalled funding requests.
- Failed or unresolved intents, expired session keys, and gas shortfall.
- Successful transactions that miss the intended resulting position.

Deduplicate by vault, condition, and incident identity. Preserve first/last observation and recovery evidence. A successful fetch does not erase an unresolved economic shortfall.

## Investigate before recovery

Attach definition version, producer timestamps, raw values/scales, intent IDs, and transaction hash. Follow [Troubleshooting](/operate/strategy/troubleshooting) to separate collection/access, evaluation, publication, execution, and outcome failures.

[Notification channels and audit polling](/operate/automation/webhooks) cover delivery and collection. Notifications are not a lossless execution ledger; reconcile state and fills independently.
