![SuperformOS Intent History](/operate/images/screenshots/history.jpg)

Filter by vault and strategy, then open the intent created after your approved activation or update. Search by intent ID, execution ID, error message, or transaction hash. Expand the row to inspect lifecycle timestamps, signal context, and fills.

## Follow the execution

| Check | What to compare |
|---|---|
| Strategy | Match the ID and publication time to the definition you reviewed. The current version may differ from the historical one. |
| Signal snapshot | Inspect the historical inputs and requested size. These are not current position values. |
| Intent | Follow its lifecycle and error, if any. |
| Execution and fills | Match execution ID, fill IDs, chain, amounts, gas, and transaction hash. An intent can have multiple fills. |
| Transaction | Open the receipt and decoded logs on the fill's chain. |
| Position | Refresh balances and risk values to check the intended outcome. |

The lifecycle includes `RECEIVED`, `ACKED`, `STAGED`, `PLANNED`, `EXECUTING`, `COMPLETED`, `ABORTED`, `EXPIRED`, `FAILED`, `CANCELED`, and `UNKNOWN` for unnormalized rows. Intent History does not record every false rule evaluation. No new row is not, by itself, proof that the rule was false.

## Verify the repayment

For the [idle-USDC example](/operate/strategy/quickstart), confirm how much USDC the repayment spent, the actual debt reduction, remaining idle USDC, and post-action debt/collateral risk values. Recompute LTV using consistent observations. A cap can leave debt above the target; interest and price changes can move it further.

A `COMPLETED` row describes execution status, not a guaranteed target LTV. If the strategy was stopped or edited, earlier intents can still settle. Reconcile them before starting a replacement or retrying the same spend.

## A recorded SuperStocks execution

The [public superNVDA AP1 history](https://os.superform.xyz/supervaults/base/0xc441a2cc3a528b6312740448a70cc4d40f4d7bfc?istr=a8d25935-9f6d-4046-a87a-82048af0cc1c&tab=intent-history) provides a **redeem-then-repay** example from 19 October 2026. Search for intent `99a5081e-9975-4cc9-82ec-fac97f355bc5`.

AP1 differs from AP0: its first hook redeems Clearstar shares, then the repayment hook consumes the USDC actually received. Its input amount is therefore raw source shares, not raw USDC.

This record establishes redemption and token flow, **not** the resulting LTV or zero debt. Before/after loan balances, interest, collateral valuation, and residual balances were not fully reconciled. To finish that check, compare the same position immediately before and after execution and account for other transactions in the interval.

## Diagnose by stage

| Symptom | Check |
|---|---|
| No intent | State, rule inputs, integer size, freshness, conviction, cooldown, occupied slot, and locks |
| Intent still executing | OMS status, error, gas, permissions, and submitted transaction before retrying |
| Failed or rejected intent | Error and receipt, then current balances and configuration before a new attempt |
| Completed but target unmet | Actual asset flows, loan balance, interest, price observations, and size caps |

Use [Strategy Troubleshooting](/operate/strategy/troubleshooting) to isolate the failure. Public detail and fills can be available without a session; the full OMS event timeline requires authorized access.

## API mapping

| Endpoint | Purpose |
|---|---|
| `GET /api/v1/intents` | Search intents with vault and strategy filters |
| `GET /api/v1/intents/facets` | Filter counts |
| `GET /api/v1/intents/{intent_id}` | Intent detail |
| `GET /api/v1/intents/{intent_id}/fills` | Fills for one intent |
| `GET /api/v1/intents/{intent_id}/events` | Authorized OMS event timeline |
| `GET /api/v1/fills` | Search fills |

These are upstream engine routes. On the SuperformOS host, the browser-facing prefix is `/api/strategy/api/v1`. See [Strategy Engine API](/operate/api/strategy) for the API reference.
