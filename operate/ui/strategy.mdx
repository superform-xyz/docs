## Read the canvas

| Visible lane | Actions | Meaning |
|---|---|---|
| Deposit | `DEPOSIT` | Deploy into a source |
| Redemption | `WITHDRAWAL`, `CLAIM` | Redeem or claim source assets |
| Rebalance | `REBALANCE`, `SWAP`, `BRIDGE`, `CLAIM_REWARDS` | Other supported movements and reward claims |

A strategy card describes a rule and action definition. Its lifecycle state, permission to edit it, and in-flight execution are different properties. RUNNING means eligible for evaluation, not proof of a successful transaction. IDLE or CREATED definitions remain visible without being active policy.

Public vault routes provide read-only strategy context and activity. Authenticated inspection depends on `canInspect`; mutation depends on `canManage` and operational gates. A public card is not a guarantee that its rule editor opens. Do not interpret a disabled edit or toggle control as an engine failure.

## Create and edit

1. Select the intended chain and vault.
2. Use **Add deposit strategy**, the redemption add control, or a rebalance add control for the intended action.
3. Select a yield source and registry-backed hook. Review its parameters and execution steps.
4. Add the boolean rule and numeric size separately. Inspect copied engine expressions, especially decimal normalization.
5. Review conviction, slippage, duration, cooldown, and concurrency.
6. Save, then reopen and compare the returned ID, version, state, rules, and plan.

Follow [Build your first strategy](/operate/strategy/quickstart) for an inactive-save exercise. **Create** and save are real configuration writes, not expression tests. Starting is a separate state change. Updates require the current version; reload and reconcile a `409 Conflict`.

The editor's quantity/type validation and metadata checks do not execute an arbitrary supplied snapshot. There is no verified dedicated **Test expression** button in this surface.

## Inspect a definition

Record the strategy ID and version before comparing behavior. Review:

- Exact source, oracle, position binding, and first-hook denomination.
- Rule tree, including guards and exact threshold boundaries.
- Numeric size, caps, and output propagation between steps.
- Whether indicators are configured and ready.
- Stored lifecycle versus kill switch, emergency target locks, and executor readiness.

[Variables and units](/operate/strategy/variables), [Rules and expressions](/operate/strategy/dsl), and [Sizing and plans](/operate/strategy/action-config) define those contracts without relying on visual shorthand.

## Order and locks

Drag within a lane to change server-managed priority. The reorder request must include every non-archived strategy in that lane exactly once. Lower numeric priority is preferred in the relevant signal group; visual order does not sequence transactions across cards.

A target-scoped emergency lock blocks publication for affected USER_DEFINED strategies and disables their related controls. Other targets can remain operable. The special `EMERGENCY_EXIT` strategy is controlled from [Pause Operations](/operate/ui/pause), not the normal editor.

A missing or expired execution session key can block automation even when a strategy is RUNNING. Upkeep, gas, hook authorization, source freshness, and liquidity are separate checks. See [Lifecycle, priority, and concurrency](/operate/strategy/lifecycle).

## Inspect activity

Open a strategy's activity in **Intent History**, then filter by vault and strategy. Follow intent ID → execution ID → fill → transaction hash. Rule evaluation alone is not a fill, and Intent History does not record every false tick. Use the [worked AP1 investigation](/operate/ui/intent-history) to distinguish recorded completion from an economically reconciled position.
