## Choose a prepared vault

Use a dedicated vault you are authorized to manage, with a configured yield source, supported deposit hook, pricing, and execution account. Complete the [launch checklist](/operate/ui/setup-checklist) first. Do not edit a running production strategy for this exercise.

Deposit only when idle exceeds 10% of vault assets, then leave 7.5% idle. The vault underlying and deposit hook's input asset must match. This is not a USDC deposit recipe for an NVDA-denominated vault.

## Author the definition

1. In **Strategy**, choose **Add deposit strategy**. Name it `Reserve deposit - inactive exercise` and select the prepared yield source and its asset-consuming deposit hook. Leave indicators empty.
2. Wait for underlying decimals and hook parameters to resolve. Check the **Size expression** denomination is the vault underlying, not source shares. **Literal** shows raw state values; **Formatted** shows decoded values. Changing this display toggle does not rewrite an existing expression.
3. In **Rule tree**, paste only `vault_tvl > 0 AND vault_free_assets > 0.10 * vault_tvl`. Use the editor's `AND` gate, **not `&&`**, and do not paste JSON. Copy returns the expression; the saved `rules` tree should be:

```json
{
  "type": "AND",
  "children": [
    {"type": "EXPR", "expr": "vault_tvl > 0"},
    {"type": "EXPR", "expr": "vault_free_assets > 0.10 * vault_tvl"}
  ]
}
```

4. Paste this complete raw-unit expression into **Size expression**, rather than entering individual human-amount chips:

```text
max(vault_free_assets - 75 * vault_tvl / 1000, 0)
```

Both inputs are raw underlying units; `75 / 1000` encodes the 7.5% target without a decimal-literal multiplication at the tested integer boundary. The VM still uses finite-precision arithmetic and intent sizing truncates, so test raw-unit boundaries. Unlike depositing all idle assets, this preserves the reserve. The first hook must consume assets, not shares. Let the registry-backed editor supply the hook, source, oracle, and `execution_params.plan.steps`; inspect the [plan shape](/operate/strategy/action-config).

5. Use **Copy** on Size expression. For this full-expression paste, expected normalized `action_config.size_expr` is `max ( vault_free_assets - 75 * vault_tvl / 1000 , 0 )`. Clipboard input is canonical DSL: the editor must not multiply this already-raw size by token decimals. Hand-entered human-value chips and explicitly decoded variable chips can compile differently; a decoded six-decimal variable compiles as `( variable / 1e6 )`. If the copied result differs beyond whitespace, stop and retest that result rather than assuming display equivalence.
6. Under **Signal & risk**, select **BINARY** in **Conviction** and enter **60** in **Cooldown (s)**. The payload contains `conviction_config.mode: "BINARY"` and `cooldown_ms: 60000`. There is **no editable concurrency control** in this editor: create/update payloads set `max_concurrent: 1`.
7. Set **Max slippage (bps)** and **Signal lifespan** for the selected venue, including a positive slippage budget on a budget-consuming plan. These controls are not a vault-wide balance lock.

## Check expected behavior

These synthetic cases were run through the actual engine compiler/evaluator. Assume a six-decimal underlying and unchanged total assets during the modeled deposit.

| Total assets, raw | Idle, raw | Trigger | Truncated deposit, raw | Idle after modeled deposit |
|---:|---:|---|---:|---:|
| `100000000` | `20000000` | true | `12500000` | `7500000` |
| `100000000` | `10000000` | false | no intent | unchanged |
| `100000000` | `10000001` | true | `2500001` | `7500000` |
| `0` | `0` | false | no intent | unchanged |
| missing | missing | false in isolated evaluator | no intent | unknown in production |

Post-action evaluation at 7.5% is false. Fees, prices, other strategies, and settlement can change the actual reserve; verify it rather than assuming the model is a fill.

There is no verified arbitrary-snapshot **Test** button in this editor. Editor validation, local evaluator tests, [model simulation](/operate/ui/simulation), transaction preflight, and mined results are different evidence.

## Save without starting

Choose **Create**, then reopen the saved definition. Confirm:

- New strategy ID and version, with the intended chain and vault.
- State `CREATED` or `IDLE`, **not `RUNNING`**.
- Copied engine rule and size match the tested expressions, including decimal normalization.
- Action `DEPOSIT` and a first plan step that consumes underlying assets.
- Correct target, execution account, hook parameters, slippage, cooldown, and concurrency.

Saving is a real configuration write; starting is separate. If the returned state is unexpectedly RUNNING, stop and investigate. Updates carry a version; on `409 Conflict`, reload and compare before resubmitting.

## Activation review

Leave this exercise inactive. For an approved rollout, review freshness, session keys, hook authorization, upkeep, execution gas, source liquidity, and competing strategies. Select the saved strategy explicitly when simulating; supported simulations load inactive definitions into RUNNING in memory without starting production automation.

After separately approved activation, follow [Intent History](/operate/ui/intent-history), then verify the reserve. Add a separate refill strategy only after checking the [reserve playbook](/operate/playbooks/reserves).
