**Browser prefix:** `https://os.superform.xyz/api/strategy`. Routes below use upstream `/api/v1` paths. The browser BFF checks the session and vault role and forwards upstream credentials server-side. Direct service writes require a separately approved integration; this reference is not a token-acquisition or writer tutorial.

`vault_id` uses `chainId_vaultAddress`, such as the public Flagship USDC vault ID `8453_0x11820afe50ea96851ee2bdbae329d97771e41ec6`. Copy the returned ID instead of reconstructing it from a differently formatted identifier.

## Access boundary

| Surface | Access |
|---|---|
| Vault-scoped strategy/intent lists and intent facets | Anonymous only for verified public vaults and allowed filters |
| Strategy detail, intent detail, intent fills, vault config | Anonymous only after resolving the owning public vault |
| Intent events, global fills, engine status/shards | Not on the anonymous allowlist |
| Create, update, lifecycle, reorder, and simulations | Manager authorization required |

Unknown anonymous query keys can be rejected, and anonymous list limits are clamped to 100. A transaction hash or execution ID alone does not establish public vault scope. See [Authentication](/operate/authentication) and the tested [public GET workflow](/operate/ui/intent-history#read-the-same-record-with-public-get).

## Strategies

| Method | Route | Purpose |
|---|---|---|
| GET | `/api/v1/strategies` | List; filter by `vault_id`, `kind`, `state`, `lane`, or `target_address`; paginate with `limit`/`offset` |
| GET | `/api/v1/strategies/{id}` | Read one definition and version |
| POST | `/api/v1/strategies` | Create a persisted `CREATED` definition |
| PUT | `/api/v1/strategies/{id}` | Update with optimistic-concurrency `version` |
| PATCH | `/api/v1/strategies/{id}/state` | Request `target_state` with the current `version`, subject to lifecycle policy |
| DELETE | `/api/v1/strategies/{id}` | Archive |
| POST | `/api/v1/strategies/reorder` | Set lane order |

Create fields include `id`, `vault_id`, `name`, `indicators`, `rules`, `action_config`, and `max_concurrent`. Priority is not a create/update field. Reorder uses `vault_id`, `lane`, and `ordered_strategy_ids`, containing every non-archived `USER_DEFINED` strategy in that lane exactly once. Do not include `EMERGENCY_EXIT` definitions.

Read back ID, version, state, rule, size, and plan after a write. On `409 Conflict`, reload and reconcile changes before retrying. Stop and reload before a risk-changing update; stopping does not cancel already submitted OMS transactions. See [safe updates](/operate/strategy/quickstart#update-an-existing-strategy).

### Action plan

`action_config` carries the action, numeric `size_expr`, objective, target, execution account, source type, and execution parameters. The current plan is `execution_params.plan.steps`, alongside `execution_params.strategy_address`. Each step specifies its hook, chain, target, arguments, amount-chaining behavior, and effects.

A legacy single-hook body containing only `execution_name` and `execution_address` is not a complete current plan. The editor builds the registry-backed configuration; [Action Config](/operate/strategy/action-config) explains what to select and inspect.

Size uses the **first step's input denomination**, not universally underlying assets. Static validation does not prove runtime arithmetic, data freshness, liquidity, or settlement. See [Strategy DSL](/operate/strategy/dsl).

### Lifecycle and locks

`USER_DEFINED` strategies use the normal canvas. System-managed `EMERGENCY_EXIT` strategies belong to [Pause Operations](/operate/ui/pause).

| Method | Route | Purpose |
|---|---|---|
| GET / PATCH | `/api/v1/vaults/{vault_id}` | Vault engine configuration |
| GET | `/api/v1/engine/status` | Engine status |
| GET | `/api/v1/engine/shards/{vault_id}/state` | Live shard state, including emergency locks |

A lock identifies `strategy_id`, `target_address`, `started_at`, and optional `reason`. It blocks user-defined publication to that target, not every strategy sharing a balance. Emergency exits do not bypass vault kill switches or rate limits.

## Intent history

| GET route | Purpose |
|---|---|
| `/api/v1/intents` | Search intent projections |
| `/api/v1/intents/facets` | Filter counts |
| `/api/v1/intents/{intent_id}` | Identity, lifecycle, summary, error, and fill count |
| `/api/v1/intents/{intent_id}/fills` | Per-intent fills and transaction hashes |
| `/api/v1/intents/{intent_id}/events` | Authorized OMS event audit |
| `/api/v1/fills` | Authorized cross-intent fill search |

Search supports `vault_id`, `strategy_id`, action/state, chain, time ranges, and other filters according to access scope. Use repeated array keys, such as `state=FAILED&state=COMPLETED`, not bracketed `state[]`. The [public example](/operate/ui/intent-history) shows a verified filter set. Use the returned `next_cursor` for continued cursor pagination when present; do not assume an older intent remains on page one.

Match `intent_id`, `strategy_id`, and `execution_id` before interpreting a fill. Lifecycle timestamps and aggregate fields can be absent while execution is in flight. Raw amounts and placeholder token addresses must not be treated as a complete economic result; follow the transaction receipt.

## Simulations

| Method | Route | Purpose |
|---|---|---|
| POST | `/api/v1/simulations/backtest` | Historical model replay |
| POST | `/api/v1/simulations/ahead` | Forward model run |
| GET / POST | `/api/v1/simulations/saved` | List or save results |
| GET / DELETE | `/api/v1/simulations/saved/{simulation_id}` | Read or delete a saved result |
| POST | `/api/v1/simulations/saved/lookup` | Find an equivalent saved result |

Explicit persisted `strategy_ids` can include `CREATED` or `IDLE` definitions. They run in memory without changing production state. Results use synthetic outcomes, not OMS submission. Lookup can load a cached result; unsupported inputs can prevent admission. See [Simulation](/operate/ui/simulation) for run, save, and load controls.
