title: "Management API"

Erebor is the SuperVaults management API. It powers vault reads, settings preparation, registries, merkle workflows, upkeep, users, pause controls, notification channels, and public vault data.

**Browser prefix:** `/api/erebor`. Tables below use upstream `/api/v1` paths. Public policies, browser-session access, and approved direct service access are distinct; see [API boundaries](/operate/api/overview). Do not obtain API credentials by extracting browser auth state.

<Note>
For onchain changes, Erebor prepares calldata and the authorized wallet signs. Offchain operations such as view-only assignment, configuration activation, redemption timing, and service control mutate state without a transaction. Verify the affected target after either type of change.
</Note>

## Access policy

| Endpoint family | Source-backed policy |
|---|---|
| Public vault list; registry GETs; proof lookup and published artifacts | Public read policies, with the route's validation and filtering |
| Vault-scoped whitelist and Merkle config reads | Public-vault read policy; private-vault authorization is separate |
| User/session/audit/service inventories and settings reads | Authenticated and scoped by the relevant handler/service; not a blanket public GET surface |
| Source whitelist preparation, config creation/activation/generation, service controls, view-only assignments | Either manager for the selected vault; UI and contract checks can be narrower |
| Fee configuration, PPS expiration, deviation threshold, banned leaves, Secondary Manager assignment, Erebor session grant/revoke preparation, proof publication | Primary Manager for the selected vault |
| Minimum-update-interval proposal/cancellation; execution preparation | Primary Manager for proposal/cancellation; either manager for execution preparation. Matured contract execution is permissionless, subject to pending-proposal and timelock checks. |

The application has its own BFF checks in addition to upstream RBAC. [Access and roles](/operate/permissions) names action-specific gates. These inventories were reviewed against source; they are not deployed-binary parity or authenticated rehearsal evidence.

## Vaults and Public Discovery

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/v1/public/vaults` | GET | Public vault list |
| `/api/v1/vaults` | GET | Authenticated vault list |
| `/api/v1/vaults/{chain_id}/{vault_address}` | GET | Full vault detail |

Vault detail includes onchain identity, managers, fees, PPS, balances, TVL, upkeep information, activation state, and allocation data when available. Authenticated list responses may include `activation`; public vault responses include `upkeep_info` and `activation` when Erebor can compute them.

Public discovery depends on more than deployment. Erebor only surfaces vaults with known activation when `activation.is_discoverable` is true. If activation is unknown because a subgraph dependency is unavailable, the vault can still be returned with `activation` unset rather than treated as deleted.

Upkeep data contributes to activation and discoverability. The implementation also supports exemptions, so activation and threshold sufficiency are not interchangeable. Inspect raw balance, threshold, shortfall, and effective policy; UP upkeep is not execution gas.

`PUT /api/v1/settings/redeem-timelock` stores an offchain timing setting; it does not prepare an onchain transaction. `DELETE` removes that setting. Read the stored value back after an approved change.

Current upkeep responses use:

| Field | Description |
|-------|-------------|
| `upkeep_info.balance` | Current upkeep balance in raw token units. |
| `upkeep_info.token` | Upkeep token address on settings responses. |
| `upkeep_info.threshold.required_balance` | Required upkeep balance for activation. |
| `upkeep_info.threshold.shortfall` | Remaining amount needed; `0` means the threshold is satisfied. |
| `activation.is_active` | Whether the vault is eligible for keeper operations. |
| `activation.is_discoverable` | Whether the vault is surfaced on public listing responses. |
| `activation.status` | `active` or `insufficient_upkeep`. |
| `activation.reason` | Optional explanation when inactive. |
| `withdrawal_status` | Pending withdrawal lifecycle; separate from `activation.status`. |

| `/api/v1/merkle/proofs` | GET | List proofs |

| `/api/v1/merkle/generate` | POST | Generate tree |
| `/api/v1/merkle/jobs/{id}` | GET | Poll generation job |
| `/api/v1/merkle/jobs` | GET | List jobs |
| `/api/v1/merkle/sync` | GET | Determine onchain sync action |
| `/api/v1/merkle/publish` | POST | Publish active proof artifact |
| `/api/v1/merkle/publish/jobs/{id}` | GET | Poll publish job |
| `/api/v1/merkle/published/{chain_id}/{vault}` | GET | Public published tree metadata |

`/api/v1/merkle/definitions` is a public upstream read policy. Omit `config_version` to resolve the active onchain root; supply it for an executed historical root. Continue with returned `tree_id` and `config_version` to pin the snapshot, following `next_offset` until null. Definitions are not cryptographic proofs. Onchain-version history omits executed roots without a completed local generation, so its total is not a count of every contract root update. Browser anonymous routing is a separate access check from this upstream policy.

## Analytics and Audit

Analytics and audit have different access policies. Vault-scoped overview, performance, risk, APY/PPS/TVL histories, fees, cohort, concentration, drawdown, retention, holders, user metrics, and volatility use upstream `publicVaultRead`: discoverable public vaults can be read publicly; private vaults require selected-vault authorization. Browser BFF anonymous routing remains a separate check.

Comparison/export, daily volume, operations summary, transaction history, and yield-source history/snapshots retain authenticated policies. Do not generalize a public vault metric to all analytics operations.

Vault-scoped analytics endpoints live under:

```bash
/api/v1/vaults/{chain_id}/{address}/analytics/*
```

Audit list, detail, and export require authenticated access. They are not a public event subscription. Use [Notifications and audit polling](/operate/automation/webhooks) for paginated polling and durable watermarks.

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/v1/audit/logs` | GET | Query audit trail |
| `/api/v1/audit/logs/{id}` | GET | Single audit row |
| `/api/v1/audit/export` | GET | Export audit rows |
